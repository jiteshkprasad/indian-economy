## Assumptions (each stated in a provenance method)

Nothing is estimated. The time series applies these rules, stated in every record's method text:
- FY rows in Rs crore at current prices; budget BE/RE rows never used; the latest vintage per (series, period); last FY 2025-26.
- Precedence inside a base: NAS 2025 statements over the API back series from 2011-12; API old-base annual sector GFCF by the latest revision round (additional revision > final > third revised > second revised > first revised > PE > SAE > FAE; verified against NAS 2025 1.1 GDP levels for every year); the BoP over older partial series from 2020-21.
- Status: official only for a published value or a pure +1 sum of lines of one table with official inputs; sign flips, differences, the back-series current-account derivation, F10 (net OS/MI + CFC) and the links are derived.
- The linked variant: linked(t) = old(t) × new(2022-23)/old(2022-23) for t ≤ 2021-22, only if both overlap ratios exist, differ by ≤ 0.02 and the flow keeps one sign.
- 2023-24 SAM check tolerances:
  - class A: max(Rs 5 crore, the summed anchored allowance tol_rel × |prior| of the matched entries);
  - class B: max(Rs 5 crore, the flow's band). Only F23 (devolution, 0.05%) is class B now; F25, F27 and F28 moved to class C (TSV-3, TSV-7);
  - class C: max(Rs 500 crore, 1%) after the clean-series bridge;
  - class D: Rs 5 crore after the bridge;
  - an explanation stays valid within max(20%, Rs 500 crore) of the residual it explains (SAM_GUIDE s.12).

## Framework requests

P-16 / FR2-2 (a post-SAM `timeseries` step with its own provenance, in the manifest and in repro) is implemented by this task, as the task allowed, with the smallest changes to shared files:
