## To U1: story figure grammar for `pipeline/export/stories/<slug>.yaml` (evaluator in `pipeline/export/stories.py`)

- [x] to U1 (done: READY: stories-eval): please implement the evaluator to this grammar (a strict superset of the PLAN §3.8 example). The three YAML files are in `pipeline/export/stories/` (`gst-rupee.yaml`, `remittance-dubai.yaml`, `deficit-funding.yaml`). Unknown keys or kinds should fail the export, naming the story and figure. My DuckDB test (`tests/export/test_export_stories.py`) recomputes every figure **value** from parquet independently and compares with `web/public/data/<v>/stories/<slug>.json`.

  Top level: `slug`, `figures` (map id -> spec), `steps` (list, copied to the JSON as PLAN §3.6 `Story.steps`; please validate that every id in `steps[*].figures` exists in `figures` and every node/link id in `steps[*].view` exists).

  Every figure has `kind`, `unit` (`inr | pct_gdp | per100 | pct`), optional `note_key` (a key in `web/messages/en/story.json`, copied through) and optional `check_equals: {ref: <id>, tol: 0.01}` (fail the export when |value - ref value| > tol).

  Selectors (used in `rows`, `cols`, `not_rows`, `not_cols`): a list whose items are account codes (`G_CEN`), groups from `pipeline/sam/accounts.yaml` (`@COM`, `@HH`, `@INST`, ...) or hierarchy nodes (`node:HH.RUR`), or `@ALL` (all 128 accounts). A bare string means a one-item list. `not_rows`/`not_cols` remove accounts from `rows`/`cols`.

  | kind | keys | value |
  |---|---|---|
  | `sam_sum` | `terms: [{rows, cols, not_rows?, not_cols?, coef? (default 1)}]` | Σ coef × balanced value of all entries in the selected cells |
  | `entries_sum` | `terms: [{rows, cols, not_rows?, not_cols?, refs?, not_refs?, components?, not_components?, coef?}]` | Σ coef × value of the matching entries. A listed ref/component that matches nothing in its term fails the export |
  | `satellite_sum` | `table: <block>/<name>` (e.g. `rest_of_world/s3_remittance_sources` = `data/sam/2023-24/blocks/rest_of_world_satellites/s3_remittance_sources.parquet`), `where: {col: value or [values]}` | Σ `value` of matching rows (zero rows fails) |
  | `satellite_share` | `table`, `share_of: {col: value or [values]}`, `within: {...}`, `total: <inline sam_sum/entries_sum spec>` | Σvalue(share_of) / Σvalue(within) × total. Split label `estimated`, method "prior split, rescaled to the balanced total" (PLAN §3.8) |
  | `ts_value` | `flow: F43`, `period: "2023-24"`, `measure: value or share` | main series per PLAN §3.7.1; `share` per §3.7.2 (× display_sign as there). Labels from the row's status (official/derived), total = that status |
  | `ratio` | `num`, `den`: each `{ref: id}` or `{gdp: "2023-24"}` | num / den |
  | `per100` | `part: {ref}`, `whole: {ref}` | 100 × part / whole |
  | `difference` | `a: {ref}`, `b: {ref}` | a − b |
  | `sum` | `terms: [{ref, coef?}]` | Σ coef × ref |
  | `prorata_sum` | `over: <selector>` (index set, e.g. `@COM`), `base: {rows, cols}`, `num: {rows, cols}`, `den: {rows?, cols?}` where the token `$` inside rows/cols stands for the current index account | Σ over a in `over` of base(a) × num(a) / den(a), skipping a where den(a) = 0 (fail if base(a) ≠ 0 and den(a) = 0). Split label `estimated`; method "proportionality assumption". Used once: the import content of household consumption (remittance story). If this is too much work, say so here and I drop that step. |

  Labels (PLAN §3.4/§3.8): `sam_sum`/`entries_sum` from their entries; `ratio`, `per100`, `difference`, `sum` take the least certain split of their parts and a total label only if every part has one (the GDP denominator counts as official). Please put the generated plain `method` string on every figure.
