## Decisions to review (for V2/V5)

- **Badges on methodology figures.** The DoD says every visible figure carries a badge. On `/en/methodology/` only GDP carries one (`<SummaryBadge path="gdp"/>`, from `summary.gdp.label`). The other bound figures are counts, rule constants and sums of labelled entries (`summary.sam.*`, `summary.methodology.*`); the contract gives them no status label, and inventing one would break SPEC §3 rule 1. Where a figure is an economic value (the X_DISC items, household factor income, the judgement-band and old-base sums), the sentence around it states its status in words ("the total is published; its split ... is estimated"). If V5 wants badges there, U1 would need to export `total`/`split` for those methodology items.
- **No-digits allowances** (`tests/unit/content/no-digits.test.ts`): besides PLAN §3.9's FY labels, SNA codes in parentheses and names such as "15th Finance Commission", the test allows decision/issue references in parentheses, e.g. "(D2-21)", "(ISSUES P1-9)", and the unit phrase "₹100" ("of every ₹100"). Both are references or units, not data. Rule constants such as the explanation threshold are bound from data (U6-1), not typed.
- **Methodology text bindings:** `<DataText path>` (U6, `components/methodology/DataText.tsx`) binds FY strings (`ts.first`, `ts.last`) because U2's `DataFig` takes numbers only. The `data-fig-path` unit test and `methodology.spec.ts` check both.
- **Sources list as cards, not a table.** PLAN §4.10 says "Sources table"; it is rendered as a list of cards (`<ul>` of `<dl>`) so it reads on a 375 px phone without a sideways-scrolling region. Each card shows publisher, licence, attribution (copied by the exporter from `data/registry.yaml`), link (withheld for RBI, never an RBI host even if the data were wrong), counts of SAM entries, time series, published totals/bands and story figures that cite it, and registry id and status.
- **Map links in the "What is estimated" section** point to the static level-0 permalinks `/en/flow/<id>/` (both presets exist at level 0), not to `/en/?p=full&x=…&s=…`, because a level-0 link id is not valid once its node is expanded.
- `map-desc.json` has no optional `components` labels (PLAN §3.9 marks them optional); the panel falls back to the ref label.
