## Fix round after verification (2026-10-02, U2 fixer)

- **V4-02 (React #418, whole-document client re-render): root cause found and fixed.** The two root layouts (`app/[locale]/layout.tsx`, `app/not-found.tsx`) imported `THEME_HEAD_SCRIPT` from `components/ui/ThemeToggle.tsx`, a `"use client"` module. A server component that imports a *value* from a client module gets a client reference, so the head `<script dangerouslySetInnerHTML={{__html: "$f"}}>` went into every page's RSC payload as `f:I[40409,[chunks…],"THEME_HEAD_SCRIPT"]`. When that chunk arrived after React had started hydrating `<head>`, hydration suspended inside the head and resumed with its cursor on `<meta charset>` while claiming `<body>`'s first child (`<a class=skip>`), hence #418 and a client re-render of the whole document. Evidence: an instrumented copy of the React chunk logged the failing fiber (`a` skip link under body < html) and the next hydratable node (`META <meta charset="utf-8">`); holding back that one chunk for 1.2 s reproduces it deterministically (404 and methodology). Fix: the script and its storage key now live in `components/ui/theme-script.ts` (a plain module), imported by both layouts and by ThemeToggle; the payload carries the string inline. Results on the same machine with V4's `vserve.mjs` (brotli) + `h418b.mjs shared`: old build 8/40 and 11/40 loads failed; new build 0/80. Late-chunk test (each referenced chunk held back in turn on 404, `/en/`, `/en/methodology/`): old 3/31, new 0/30. Regression tests in `tests/e2e/smoke.spec.ts`: every client reference in every inline payload must name a component (`default` or PascalCase), and "hydration survives any one late script chunk". Still to do at Checkpoint C (orchestrator): re-check the Vercel preview console.
- **V4-04 (RSC prefetch on first view): fixed.** `@/i18n/navigation`'s `Link` now defaults to `prefetch={false}` (a caller may pass `prefetch` to opt in), so no unit's links prefetch on view; Header and Footer also pass it explicitly. Measured on the built site: `/en/` 15 RSC files / 1,453 KB raw before, 0 after; `/en/methodology/` and `/en/data/` 9 / 554 KB before, 0 after. Client-side navigation still works (header links and story cards navigate softly, no reload, no errors). The story payloads themselves (about 300 KB raw each, V4-09) are U5's.
- **V4-05 (`/_next/static` caching): fixed.** `vercel.json` adds `/_next/static/(.*)` → `public, max-age=31536000, immutable` (every file there is content-hashed or under the build-id folder) and `"trailingSlash": true` (`/en` → 308 `/en/`, files with extensions are not redirected). `headers.spec.ts` checks both rules and that the local server sends the immutable header for a chunk the home page references but not for an HTML page. `scripts.test.ts` updated for the new header order.
- **V5-02 / V2-08 (an "Official" figure saying "The total is not held to a single published figure"): fixed in StatusBadge.** New prop `single`: the figure is one published or derived value (GDP, one year of a series), not a sum of entries, so the panel has no total line at all. It defaults to true when the caller passes no `composition`, `pins` or `pairPins` (a figure with no parts is not a sum); aggregates always pass their composition. For aggregates, the panel now first says "This amount adds up several entries of the accounts. The label for how its parts were made is the least certain kind of entry that carries at least 10% of the value:" and the unpinned line reads "The sum itself is not held to a single published figure." So an all-official but unpinned link (PRDS--PROD) no longer reads as a contradiction. U3's fixer already passes `single` for the GDP card and the series value (and chose `total = summary.gdp.label` for GDP; that is U3's call).
- **V5-05 (pins shown as raw ids): fixed.** The badge panel lists each pin as the figure it is: a constraint by its `description` from `sam/constraints.json`, its target and its tolerance (`<Num>`-bound, e.g. "Published NAS household residual; … Target ₹5.71 lakh crore; the balanced total is within ₹1.0 crore of it."), a time-series pin by the series name from map-text ("The time series “Household consumption (PFCE)” (F01); the 2023-24 accounts match it (its check passes)."). `constraints.json` (129 KB) loads only when a panel with constraint pins is opened (`useConstraints(need)`); map-text comes from `<MapTextProvider>` or, on pages without it (`/en/data/`), a lazy import (`useMapTextLazy`). If a file fails, the panel says which and lists the ids; it never invents text. No caller change is needed.
