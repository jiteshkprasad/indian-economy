## Framework requests
- **FR1:** a survey-year `period_type` (e.g. `sy` with 'YYYY-MM/YYYY-MM' or 'Aug2023-Jul2024'), or an optional `period_note` column, so HCES, PLFS and NSS rounds are not forced into `fy`.
- **FR2:** units `kg`, `litre`, `gram`, `metre` and `kWh` (or a generic physical unit with the unit in `dim_other`). Per-person quantities in tonnes are awkward, and litre/gram quantities cannot be stored at all.
- **FR3:** an opt-in legacy-renegotiation TLS context for api.mospi.gov.in in `ctx.fetch` (already raised in ACCESS_PLAN s.3). It would enable the eSankhyiki HCES and CPI item-index APIs.
- **FR4:** round to significant digits, or to more than 6 decimals, for `percent` / `ratio` rows. Small weight shares lose relative precision.

- **FR5:** `tests/clean/test_clean_datasets.py::test_file_is_canonical` should honour `Dataset.ratio_sig_digits`. When `_datasets.json` records `ratio_sig_digits` for a dataset, re-serialise with `decimals={"value": None}`, as the runner's writer does. Without that, any dataset that opts in fails the generic test (seen here on `hces_consumption_cpi2024_weights`, sha fd1de088... expected vs 20ae667a... on disk), so the FR4 opt-in cannot be used. Once fixed, this unit will set `ratio_sig_digits=9` on the CPI weights (hces_consumption-12).

**Framework close-out (2026-09-29):** FR1 survey period: DONE (`sy`, e.g. '2023-08/2024-07'). FR2 `kg`, `gram`, `litre`, `metre`, `kWh`: DONE. FR3 legacy TLS: DONE. FR4: DONE as opt-in `Dataset(..., ratio_sig_digits=N)` for percent/ratio rows. Using them is a unit change. Dispositions: `docs/phase1/FRAMEWORK_REQUESTS.md`.
