- **FR-1 (blocks S6):** add an energy unit to `pipeline/core/units.UNITS`, e.g. `"PJ": "Petajoules (energy quantity; physical energy accounts)"`. `pipeline/ingest/io_tables/energy.py` emits `io_tables_energy_psut` automatically once the key `PJ` exists (and `test_psut_not_emitted_until_unit_exists` flips). `KToE` would be useful for the energy balance too.
- **FR-2 (optional):** `EUR_million` if FIGARO is wanted as a second import-matrix prior (io_tables-10).
- **FR-3:** `repro <unit>` compares a `code_hash` over the whole `pipeline/` tree, so any other agent's edit during the three builds fails the command (io_tables-15). Suggest hashing only `pipeline/core`, the CLI and the unit's own files (and its DEPENDS) for a unit-scoped repro.
- **FR-5 (optional, low priority; io_tables-17b):** a significant-digit opt-in for physical-unit rows, like `ratio_sig_digits` (e.g. for `PJ`), so a small printed energy value keeps its printed digits. It affects one value today (0.16179072 stored as 0.161791), so nothing depends on it.
- **FR-4 (orchestrator choice, io_tables-12):** the IFPRI data paper is fetched under the registry addition `ifpri_nexus_sam_india_2022_23_paper`. PIPELINE_GUIDE s.4 says a public part of a refused source should instead be a `PUBLIC_PARTS` entry. The alternative is to add `ifpri_nexus_sam_india_2022_23` with the prefix `https://cgspace.cgiar.org/server/api/core/bitstreams/ff7b1ece-8897-4567-be3a-4c99db75dca3/` (reason: open data paper, CC BY 4.0; the Dataverse SAM.tab behind the guestbook is not used) to `policy.PUBLIC_PARTS`, then switch the unit's source id. The paper is a separate CGSpace item (own handle, Open Access, CC BY 4.0), so the registry addition is also defensible. Either way, the only code change is the source id in `ifpri.py`/`fetching.py`.

## S6 follow-up (29 Sep 2026, after the framework close-out)

What changed (unit files only):
- `pipeline/ingest/io_tables/energy.py`: the `if 'PJ' not in UNITS` gate and its warning are removed (the unit now
  exists; a missing unit would fail the runner's unit check anyway). Labels go through `clean_label` (no label
  changed). The columns now carry proper dimensions instead of every printed column sitting in `industry`: `industry`
  only on the 7 industry columns (`isic_a`, `isic_b`, `isic_c`, `isic_d`, `transport_storage`, `construction`,
  `other_industries`); `institution=households`; `counterparty=rest_of_world` (imports, exports) or `environment`
  (flows from/to the environment); `product` = the SIEC class slug on energy-product and natural-input rows; and
  `dim_other` `psut_column=<column>` on every row, so accumulation, statistical difference and Total stay
  addressable. Before this, `industry` held values like `households`, `exports` and `total`, so a filter on
  `industry` for S6 would have mixed in non-industry columns. `series_id`, `value`, `item_label`, `table_id` and the
  provenance records are unchanged (324 rows, same 4 prov records).
- `pipeline/ingest/io_tables/__init__.py`: the docstring lists the dataset; the FIGARO note says EUR_million now
  exists (io_tables-10 stays open).

  period 2023-24, 37 series = Table 9.2 (B) end use of 6 energy products plus transformation inputs, by the 7
