## Framework requests
- **fetch_file: reconcile the sidecar when reusing an existing raw path** (trade_satellites-14). When `_new_raw_path` returns an existing file with identical bytes whose `.meta.json` came from an earlier, interrupted run, `fetch_file` should either keep that meta's `retrieved_at` in the new pin or rewrite the meta. Separately, `PinStore.save` could retry `os.replace` briefly on Windows `PermissionError` (a reader holding the YAML open).
- **Form POST with a same-session CSRF token** (for TradeStat; trade_satellites-1): `ctx.fetch(..., form_body={...}, session=<token from a prior GET of the same host>)`, keeping only cookies the site sets inside that one request chain. ACCESS_PLAN §3 calls these "ordinary". This is an orchestrator decision, and the DGCI&S permission question stands on its own.

**Framework close-out (2026-09-29):** sidecar reuse fixed (the pin now takes the existing sidecar's `retrieved_at`) and `PinStore.save` retries on Windows PermissionError: DONE; the -14 pin was repaired, which changed two provenance ids and re-pointed 512 comtrade rows (values unchanged). Form POST with a CSRF/session token: REJECTED (D1-7). Dispositions: `docs/phase1/FRAMEWORK_REQUESTS.md`.
