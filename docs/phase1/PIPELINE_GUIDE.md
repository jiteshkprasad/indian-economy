# Pipeline guide: the contract for ingest units (Phase 1)

Read `SPEC.md` §3, `DECISIONS.md` (D1-1 access policy, D1-2 no microdata) and your source family's notes in `docs/phase0/recon/` and `docs/phase0/verify/` first. The working template is `pipeline/ingest/mospi_nas_2026.py`, with its tests in `tests/units/test_mospi_nas_2026.py`. Copy its patterns.

Two meanings of "unit" appear below. An **ingest unit** is your module. The **`unit` column** is the unit of measure.

## 1. What you own, and what you must not touch

| You own (create/edit freely) | Never edit |
|---|---|
| `pipeline/ingest/<unit>.py` or the package `pipeline/ingest/<unit>/` | `pipeline/core/*`, `pipeline/cli.py`, `pipeline/__main__.py` |
| `pipeline/ingest/<unit>_coverage.yaml` | other units' modules, tests, pins, clean data, issue files |
| `tests/units/test_<unit>.py` (or `tests/units/<unit>/`) | `pyproject.toml`, `uv.lock`, `justfile`, `.gitignore`, `.gitattributes` |
| `data/raw_pins/<unit>.yaml` (written by `fetch`; never by hand) | `data/registry.yaml`, `data/gap_map.csv`, `ISSUES.md`, `DECISIONS.md`, `SOURCES.md` |
| `data/clean/<unit>/` (written by `build`; never by hand) | anything in `data/raw/` (fetch writes it; never edit or delete by hand) |
| `data/registry_additions/<unit>.yaml` (only if you need a new source; see §8) | `data/manifest.json` (regenerated by `build`) |
| `docs/phase1/issues/<unit>.md` | |

- Do not commit. The orchestrator commits.
- If you need something in `pipeline/core` (a new unit of measure, a helper), write it in your issues file under "Framework requests". Do not work around it. Every request made in Phase 1 and what was done with it is in `docs/phase1/FRAMEWORK_REQUESTS.md`.
- The environment already has polars, pandas, pyarrow, numpy, scipy, duckdb, openpyxl, xlrd, fastexcel, python-calamine, pyxlsb, odfpy, pdfplumber, pypdf, lxml, beautifulsoup4, rapidfuzz, httpx and python-dateutil. Do not add packages.

## 2. Commands

`just <recipe>` and `uv run python -m pipeline <command>` are identical, including quoted arguments (`just test -k "s1_1 and not live"`); `just` is only a shortcut. Run from the repo root (PowerShell or Git Bash).

```
uv run python -m pipeline fetch <unit>            # network: download + pin raw files (polite, cached)
uv run python -m pipeline fetch <unit> --offline  # verify the cache only, no network
uv run python -m pipeline fetch <unit> --refresh  # re-download; changed upstream bytes -> new pin (warning)
uv run python -m pipeline fetch <unit> --prune    # drop pins this run did not request (only after a clean run)
uv run python -m pipeline build <unit>            # offline: pinned raw -> validated data/clean/<unit>/ + manifest
uv run python -m pipeline build <unit> --with-deps  # also rebuild the units in your DEPENDS (normally not)
uv run python -m pipeline test                    # all offline tests (live tests excluded)
uv run python -m pipeline test -k <unit>          # your unit tests + the generic tests on your data and files
uv run python -m pipeline test -m live            # network canaries
uv run python -m pipeline repro <unit>            # build 3 times (2 hash seeds, 1 and 4 threads), byte-identical;
                                                  # only <unit>'s own files (code, YAML, JSON specs; + pipeline/core, uv.lock) must stay unedited
uv run python -m pipeline coverage <unit>         # gap-map coverage of your unit's entries only
uv run python -m pipeline list                    # units, sources, pins, datasets
```

The CLI pins `PYTHONHASHSEED=0`, single-threaded BLAS and polars, and UTF-8 I/O by itself. Always go through it; don't call `pytest` directly. Generic tests are parametrised with ids that contain the unit name (`<unit>/<dataset>.parquet`, `crlf-<unit>`, `order-<unit>`, `test_registry_additions_valid[<unit>]`), so `-k <unit>` selects yours. If the only failures belong to another unit (or to `crlf-shared` / `order-shared` files you did not touch), they are not yours to fix.

## 3. A unit in 40 lines

```python
"""<Publisher> <publication>: what this unit ingests, the vintage, and anything skipped (and why)."""
from __future__ import annotations

import polars as pl

from pipeline.core.unit import BuildContext, Dataset, FetchContext
from pipeline.core.units import clean_label, conversion_note, normalize_fy, parse_number, to_inr_crore

UNIT = "rbi_example"                       # == module name; lower snake_case
SOURCES = ["rbi_hbs"]                      # registry ids this unit reads (hard error if unknown)
URL = "https://www.rbi.org.in/.../T1.xlsx"

def fetch(ctx: FetchContext) -> None:       # the ONLY place with network access
    ctx.fetch("rbi_hbs", URL, name="hbs_t1.xlsx", referer="https://www.rbi.org.in/...landing")

def build(ctx: BuildContext) -> list[Dataset]:  # offline; must be deterministic
    raw = ctx.raw("rbi_hbs", "hbs_t1.xlsx")      # pinned, hash-verified bytes
    pid = ctx.prov(raw=raw, table_id="Table 1", locator="sheet 'T1', rows 6-40, cols B:K",
                   unit_as_published="Rs lakh crore", conversion=conversion_note("INR_lakh_crore"),
                   price_basis="current", vintage="2026-09-15", release="Handbook 2025-26 (RBI, 15 Sep 2026)")
    rows = []
    for label, year, cell in parse_somehow(raw.path):          # your parsing
        v = parse_number(cell)                                  # Indian formats, '-', 'NA', '(1,234)'
        if v is None:
            continue                                            # published as missing: no row
        rows.append({"series_id": "t1.gross_saving.current", "source_id": "rbi_hbs",
                     "table_id": "Table 1", "item_code": "gross_saving", "item_label": clean_label(label),
                     "geography": "IN", "stock_flow": "flow", "period": normalize_fy(year), "period_type": "fy",
                     "value": to_inr_crore(v, "INR_lakh_crore"), "unit": "INR_crore", "price_basis": "current",
                     "vintage": "2026-09-15", "estimate_stage": "Provisional", "status": "official",
                     "prov_id": pid})
    return [Dataset(f"{UNIT}_t1", pl.DataFrame(rows), "Handbook Table 1, gross saving, 1950-51 to 2025-26")]
```

`Dataset(name, df, description)` needs a one-line description; it goes into `data/clean/<unit>/_datasets.json`. The runner then adds `dataset` and any null dimension columns. It validates everything below, checks every `prov_id` and `source_id`, and writes `data/clean/<unit>/<dataset>.parquet`, `_provenance.parquet` and `_datasets.json` through the deterministic writer. Finally it regenerates `data/manifest.json`. If anything fails, nothing is written and the previous output stays. The new output is written to a temp folder and swapped in with renames. On Windows the swap is refused if a file in `data/clean/<unit>/` is open in another process (a notebook, a viewer, a test run); the build then fails with "previous output is unchanged". Close the file and rebuild.

**Module layout.** Every non-underscore module in `pipeline/ingest/` must be a unit. Helpers go inside your package (`pipeline/ingest/<unit>/helpers.py`) or in a private module named `_<unit>_*.py`. You cannot share helpers with another unit: copy them, or put a "Framework request" in your issues file.

**Reading another unit's output** (rare; e.g. an `INR_per_USD` series for a dollar conversion): declare `DEPENDS = ["<other unit>"]`, read it with `ctx.clean("<other unit>", "<dataset>")`, and list its rows' `prov_id`s in your derived record's `inputs`. `build <unit>` reads dependencies as already built by their owners and fails if one is missing; it never rewrites another unit's `data/clean/<other>/` unless you pass `--with-deps` (do that only when you own both, or in a scratch `--out` folder). `build` with no unit, and `repro`, build dependencies first. The runner checks that the foreign `prov_id`s exist. Never read `data/clean` by path inside `build()`.

Parse by **label, not by row number**. Assert the header texts and units you rely on, as the template's `_expect()` does, and raise when a label is unmapped or a cell you expect is blank. A statement that changes shape must fail loudly, never ingest shifted numbers.

## 4. Fetching (DECISIONS.md D1-1)

- `ctx.fetch(source_id, url, name=None, *, method="GET", json_body=None, headers=None, referer=None, expect=None)` is the only way to download. Never import httpx, requests or urllib in a unit.
  - `name` is the pin key and the file name. Default: the last URL segment. Allowed characters: `A-Za-z0-9._-`. It must be unique within your unit for that source; prefer the publisher's table id (`hbs_t12.xlsx`, not `T1.xlsx`).
  - `method="POST", json_body={...}` covers a public JSON API that the site's own page calls (e.g. the MoSPI listing).
  - `method="POST", form_body={...}` submits a public, keyless HTML form, e.g. an ASP.NET archive page's postback (PIB `allRel.aspx`): GET the page first (pinned), read its hidden `__VIEWSTATE`/`__EVENTVALIDATION` fields, and post them back with the form fields (DECISIONS D1-7). Fields are sent in the order given, so use a dict literal. The pin records the hash of the encoded body. Fields that look like credentials, a session id or a CSRF token (`password`, `_token`, `csrf...`, `...SessionId`, `api_key`, `captcha`, ...) are refused before any request: flows that need a server session and CSRF token (e.g. Commerce TradeStat) stay out of scope.
  - `headers` may set only `Accept`, `Accept-Language`, `Range` and `X-Requested-With`; anything else (cookies, tokens, keys, `Authorization`) is refused before any request. Set the Referer with `referer=`.
  - `expect` is the file kind to verify: `xlsx`, `xls`, `pdf`, `csv`, `json`, `html`, `zip` or `any`. The default comes from the name's extension.
- What `ctx.fetch` does for you:
  - sends browser-like headers;
  - waits at least 2 s per host, across every process on this machine (locks in `%LOCALAPPDATA%\india-sam\host-locks`, or `~/.cache/india-sam/host-locks`, whatever data folder or checkout the process uses). Some hosts need longer: `fetch.HOST_MIN_INTERVAL_S` sets **10 s for `rbidocs.rbi.org.in`** (D1-4), enforced through the same lock, so units need no `time.sleep` of their own;
  - **stops a host at its first bot challenge** (D1-1b, D1-4). A challenge raises `ChallengeServed` (a subclass of `AccessBlocked`), and every later `ctx.fetch` to that host in the same run raises `ChallengeServed` at once, without contacting it. A plain 403/404 is not a challenge and does not stop the host;
  - uses legacy TLS renegotiation only for the hosts in `fetch.LEGACY_RENEGOTIATION_HOSTS` (**`api.mospi.gov.in`**, the eSankhyiki API; D1-6). Certificate and host-name checks stay on. Any other host that fails with `UNSAFE_LEGACY_RENEGOTIATION_DISABLED` needs a Framework request;
  - follows redirects itself, one hop at a time, each through the same 2 s wait and policy checks, and records the chain in the `.meta.json`;
  - retries timeouts, 429 and 5xx with backoff;
  - verifies TLS with the OS trust store;
  - saves `data/raw/<source_id>/<YYYY-MM-DD>/<unit>/<name>` plus `<name>.meta.json` and pins the sha256 in `data/raw_pins/<unit>.yaml` (the unit in the path means two units never collide on a name);
  - never overwrites a file: a second version on the same day goes to `<YYYY-MM-DD>-r2/`.
- A second `fetch` does no network I/O while the pinned file is present. `ctx.is_pinned(source_id, name, url=None)` tells you in advance whether a `ctx.fetch` will reuse the local pinned copy (pin present, file on disk, not `--refresh`, same URL if given); use it instead of reading `ctx.store` internals. `--refresh` re-downloads. If the bytes changed, it writes a new file and a new pin, keeps the old pin under `history`, and raises a `REVISION` warning (shown in the run summary). Record every revision in your issues file, then re-check your expected values.
- After a successful `fetch`, pins that this run's `fetch()` never requested are listed in the log. If they are really obsolete, `fetch <unit> --prune` drops them; it refuses when the run had any warning (a skipped or blocked file must keep its pin). Raw files are never deleted.
- If the pinned file is missing locally (a fresh clone) and upstream now serves different bytes, a plain `fetch` fails: the pinned version can no longer be had. Accepting the new one is a revision, so run `fetch <unit> --refresh` and treat it as above.
- **`AccessBlocked`** (or its subclass `ChallengeServed`) is raised, and nothing is saved, for:
  - HTTP 401/403/407/451, or 429 after retries;
  - a bot challenge (F5/TSPD, Cloudflare, Imperva, CAPTCHA) with any status, including 503; a challenge is never retried;
  - a sign-in or registration page (a redirect to `/login`, `/sso`, `login.<host>`...) or a page with a password field;
  - an HTML page where a file was expected;
  - a `Retry-After` longer than 120 s (we stop instead of retrying early; fetch again later);
  - anything the access policy refuses (next bullet).

  What to do:
  - Do not retry with other headers, cookies, a browser, mirrors of doubtful origin, or by solving challenges.
  - Log it (§9). You may catch it only to continue with the unit's other files, and your build must not need the blocked file.
  - MoSPI answers 403 for files that do not exist, so check the URL first.
- **The access policy is enforced in code** (`pipeline/core/policy.py`); a unit whose `SOURCES` break it fails its contract check.
  - Refused sources: GSTN and CBDT (D1-1c: ids `gstn_*`, `cbdt_*`), unit-level microdata (D1-2: `*_unit_data`, `*microdata*`), any source whose landing page is on a denied host, and any source whose registry `access.requires` is not `none` (registration, login, api_key, paid, manual_download).
  - Denied hosts, including on redirects: `gst.gov.in`, `incometax.gov.in`, `incometaxindia.gov.in`, `microdata.gov.in` and their subdomains.
  - Public parts of otherwise-restricted sources are allowed only under listed URL prefixes (`PUBLIC_PARTS`): the ASI keyless API and PDFs (`mospi_asi`), CAG public PDFs (`cag_state_finance_accounts`), and the UN Comtrade keyless preview (`un_comtrade`). If another source has a public part, file a Framework request; do not work around the refusal.
  - Use the substitutes named in D1-1c (Finance Accounts, Budget documents, PIB), or log the gap.
- RBI files are for internal processing only (D1-1d). That is fine for the pipeline; the raw files are never committed.

## 5. The clean table (one row = one number)

Columns (`pipeline/core/schema.py`). **R** = required; the rest may be omitted, and the runner then adds them as null.

| column | rule |
|---|---|
| `series_id` R | lower-case `[a-z0-9_.-]`, unique within the dataset for one line item + dims + unit + price basis. Convention: `<table>.<item_code>[.<dim values>].<price_basis>`, e.g. `s1_1.gdp.current`, `t12.deposits.scb.current`. The global id of a series is `(dataset, series_id)`. |
| `source_id` R | a registry id listed in your `SOURCES` |
| `table_id` R | the publisher's table/statement id as printed, e.g. `Statement 1.1`, `Table 42` |
| `item_code` R | your stable snake_case code for the line item (`gdp`, `pfce`, `interest_payments`) |
| `item_label` R | the English label as published, passed through `clean_label()` |
| dims | `institution`, `industry`, `product`, `instrument`, `counterparty`, `geography`, `household_group`, `side`: **codes without spaces**. Use the publisher's code where one exists (NIC, HS, COICOP, SUT product number), otherwise a documented snake_case slug. `geography` is checked: exactly `IN`, a State/UT code from `pipeline/core/geo.py` (§5.3), or a partner's ISO 3166-1 alpha-3 code (`USA`); country groups (EU, OPEC, ...) go in `dim_other` (e.g. `region=eu`). `side`: `credit`/`debit`/`net`, `receipts`/`payments`, `assets`/`liabilities`, `uses`/`resources`. Anything else goes in `dim_other` as `key=value;key=value` with unique keys in sorted order (checked). |
| `stock_flow` R | `flow`, `stock` (outstanding at a date) or `n/a` (rates, shares, indices) |
| `period`, `period_type` R | see §5.2 |
| `value` R | Float64, finite, never null or NaN. If a cell is published as missing, emit no row. It is rounded to 6 decimals on write (see `ratio_sig_digits` in §5.1 for small percent/ratio values). |
| `unit` R | vocabulary in §5.1 |
| `price_basis` R | `current`, `constant_YYYY_YY` (e.g. `constant_2022_23`, `constant_2011_12`) or `n/a` |
| `base_year` | `YYYY-YY` of the series' base (NAS: `2022-23` new series, `2011-12` old). Required for constant prices and must match the price basis. |
| `vintage` R | publication date of the release the number comes from: `YYYY-MM-DD` (or `YYYY-MM` / `YYYY` if only that is known). It must be a real date, not before 1947 and not after today. For `official` rows (except `BE`), a period may not start after the vintage. Several vintages of one series may sit in one dataset. |
| `estimate_stage` R | `Final`, `TRE`, `SRE`, `FRE`, `PE`, `SAE`, `FAE`, `AE`, `QE`, `BE`, `RE`, `Actuals`, `Provisional`, `Revised`, `Partially Revised` (RBI's "PR" flag), `Preliminary`, `Audited`, `Unaudited`, `n.a.` |
| `status` R | `official` (as published, after pure unit conversion), `derived` (our arithmetic on official numbers, e.g. a US$→₹ conversion or a sum), `estimated` (modelled or imputed). The UI shows `estimated`. |
| `prov_id` R | from `ctx.prov(...)` |

The key `(dataset, series_id, vintage, period)` must be unique. Within one `series_id`, these must not vary: source, item_code, dims, stock_flow, period_type, unit and price_basis.

**Dataset names** must equal the unit id or start with `<unit>_`, in snake_case: `mospi_nas_2026_s1_1`. Use one dataset per published table, or per coherent group of tables.

### 5.1 Units of measure (convert on the way in)
`INR_crore` (the default for all money), `INR` (per-capita and per-unit amounts), `USD_million`, `USD`, `INR_per_USD`, `EUR_million`, `percent` (12.5 = 12.5%), `ratio`, `index`, `count` (never in thousands or lakh), `years`, and physical quantities `tonnes`, `kg`, `gram`, `litre`, `metre`, `kWh`, `PJ` (petajoules), `KToE` (kilotonnes of oil equivalent). The full list with definitions is `pipeline/core/units.UNITS`.

- Physical quantities: keep the unit the source prints (a table in grams stays in `gram`). Never convert between physical units inside a unit; that is Phase 2 work with its own provenance.
- Euro: keep `EUR_million`. There is no `INR_per_EUR` series yet, so the runner refuses rupee rows whose provenance caption is in euro, and refuses a rupee caption on euro rows. `inr_unit_from_label` refuses euro captions.
- **Small shares** (`ratio_sig_digits`): the writer rounds every value to 6 decimals, which leaves a weight share such as 0.000123456 with only 3 significant digits. `Dataset(name, df, description, ratio_sig_digits=9)` rounds that dataset's `percent` and `ratio` rows to 9 significant digits instead, but never to fewer than 6 decimals and never beyond 15, so opting in only ever keeps more precision. Other rows keep 6 decimals. The setting is recorded in `_datasets.json`.

- Rupees: `inr_unit_from_label("(Rs '000 crore)")` → `INR_thousand_crore`; `to_inr_crore(value_or_expr, that_key)`; `conversion_note(key)` gives the text for provenance. Lakh, thousand crore, ₹ '000, million, billion and trillion are all handled.
- Dollars: keep `USD_million` when the source publishes dollars. Convert to ₹ only with `usd_million_to_inr_crore(values, rates)`, where `rates` is a clean `INR_per_USD` series with its own `prov_id`. The converted rows are `derived`, and their provenance `inputs` must include the rate's `prov_id`. **Never hard-code an exchange rate.**

### 5.2 Periods
| period_type | format | example |
|---|---|---|
| `fy` | Indian fiscal year (April–March) `YYYY-YY` | `2023-24` |
| `fq` | fiscal quarter, Q1 = April–June | `Q1 2026-27` |
| `fh` | fiscal half-year | `H1 2023-24` |
| `cy` / `cq` | calendar year / quarter | `2024` / `2024-Q1` |
| `month` | `YYYY-MM` | `2024-12` |
| `date` | a stock at a date (a real calendar date) | `2024-03-31` |
| `sy` | a survey window that is not a fiscal year: first and last month, inclusive, `YYYY-MM/YYYY-MM` | `2023-08/2024-07` |

- Use `normalize_fy()` on messy headers such as `2023-2024`, `2023–24`, `2024-25 (FRE)` or `FY 2023-24`; it raises on anything ambiguous.
- `2011-12` is both FY 2011-12 and December 2011, which is why every row carries `period_type`.
- An RBI "end-March 2024" stock is `date` `2024-03-31`, not `fy`.
- **Surveys** use `sy` whenever the survey year is not April-March: HCES 2023-24 (August-July) is `2023-08/2024-07`; a PLFS or SAS agricultural year (July-June) 2023-24 is `2023-07/2024-06`; ASUSE 2023-24 (October-September) is `2023-10/2024-09`. Build labels with `units.survey_period(start_year, start_month, months=12)` or `units.agricultural_year(start_year)`, never by hand. Do not force a survey into `fy` and do not describe the survey window in `dim_other`. A survey that really runs April-March is `fy`; one that runs January-December is `cy`. The label is the window, not the survey's name: the survey's own label ("PLFS 2023-24") goes in `item_label`/provenance.
- `units.period_start()` and `units.period_end()` give the first and last day of any period; `units.period_sort_key()` is the start of a period across types (periods starting in the same month tie, e.g. FY 2023-24 and 2023-04, or two survey windows from 2023-07); `units.period_order_key()` is a total order (start, then end, then label) for when ties matter.

### 5.3 States and Union Territories (DECISIONS D1-9)
One code set for the whole project lives in `pipeline/core/geo.py`, and the schema rejects any other `IN-..` code.

- **Current codes**: ISO 3166-2:IN after ISO's change of 23 November 2023, verified live on 29 Sep 2026 (sources in the module docstring): 28 States and 8 UTs. Note **`IN-CG` Chhattisgarh, `IN-OD` Odisha, `IN-TS` Telangana, `IN-UK` Uttarakhand** (the older `IN-CT`, `IN-OR`, `IN-TG`, `IN-UT` are refused), `IN-CH` is Chandigarh, `IN-LA` Ladakh, `IN-JK` the UT of Jammu and Kashmir, and `IN-DH` the merged UT of Dadra and Nagar Haveli and Daman and Diu.
- `geo.state_code("Orissa")` maps printed names and common variants to codes and raises on anything unknown; `geo.state_name(code)` goes the other way.
- **Historical territories** have non-ISO project codes, so a row's geography always means one fixed territory: `IN-XAP` undivided Andhra Pradesh (to 1 Jun 2014), `IN-XJK` the State of Jammu and Kashmir including Ladakh (to 30 Oct 2019), `IN-XDN` Dadra and Nagar Haveli and `IN-XDD` Daman and Diu (to 25 Jan 2020), `IN-XMP`, `IN-XUP`, `IN-XBR` undivided Madhya Pradesh, Uttar Pradesh and Bihar (to Nov 2000). Use them for periods before the reorganisation; `geo.HISTORICAL` has the exact dates. `state_code()` never returns them: only your unit knows the period.

## 6. Provenance

`ctx.prov(raw=..., table_id, locator, unit_as_published, price_basis, vintage, release, base_year=None, conversion="none", status="official", method=None, inputs=(), notes=None)` returns a `prov_id`.

- Make one record per block of cells that shares every field. `locator` must let a verifier find the number in the original file within a minute: sheet name, cell range and year columns, or page and table.
- The row's `source_id`, `status`, `price_basis` and `vintage` must equal its provenance record's; the runner checks this.
- `derived` and `estimated` records need a `method` (plain English, precise enough to reproduce). `raw` may be `None` for them (pass `source_id=`), but then the record must still say where its numbers come from:
  - a `derived` record needs `inputs` (the `prov_id`s it is computed from) or `raw`;
  - an `estimated` record needs `inputs`, `raw`, or `notes` citing the document or assumption behind it.
- `unit_as_published` describes this block only (one record per unit of measure), and the runner checks it against the rows' `unit`:
  - `INR_crore` rows of an `official` record need a rupee caption that `units.inr_unit_from_label` understands (`Rs crore`, `Rs lakh`, `Rs '000 crore`, ...);
  - whenever the caption is a rupee unit, `conversion` must start with `units.conversion_note(<that unit>)` (`none` for crore, `INR_lakh -> INR_crore: x 0.01` for lakh, ...);
  - rupee rows whose record says US$ must be `derived`, with an `INR_per_USD` series among `inputs`. The rate series must exist as rows, in your unit or in a unit in DEPENDS;
  - dollar rows (`USD_million`, `USD`) must not carry a rupee caption.
- Retrieval date, URL, file hash and path come from the pin automatically. Never type them.

## 7. Tests you write (`tests/units/test_<unit>.py`)

The generic tests in `tests/clean/` and `tests/raw/` already cover schema, units, provenance, registry ids, duplicate keys, canonical bytes and raw hashes for every unit. Your file adds **value** tests. The template shows the first three kinds:

- **Anchor values** from the document itself, with a comment saying where each is printed (press release, table, page). Include at least one reference-year (2023-24) number per dataset.
- **Identities**: `checks.check_identity(df, total, {part: ±1})`. Use it for components summing to totals, and for cross-table agreement. For tables that print '-' for a category that did not exist yet, pass `missing_parts_as_zero=True`: an absent part then counts as 0 (a missing total is still reported).
- **Ranges and continuity**: `checks.check_range`, `checks.check_continuity`. A flagged break must be either explained in the test or logged.
- **Revisions**: `checks.compare_vintages` when a dataset holds several vintages.
- Always wrap a check with `checks.assert_no_rows(violations, "what")`. Load data with `checks.load_dataset(unit, dataset)`.
- Mark tests that need the network with `@pytest.mark.live`.

## 8. Coverage and new sources

**Coverage.** `pipeline/ingest/<unit>_coverage.yaml` maps the `data/gap_map.csv` refs your data serves; the format is in `pipeline/core/coverage.py`, with an example in `mospi_nas_2026_coverage.yaml`. Use `extent: full` only when your data fills the cell by itself. Use `partial` or `control_total` otherwise. Check with `uv run python -m pipeline coverage <unit>`: a `BROKEN` entry of your unit fails the command. Plain `coverage` reports every unit, so another agent's unfinished entry can make it fail.

**New sources.** If you need a source that is not in `data/registry.yaml`, add it to `data/registry_additions/<unit>.yaml` with `unit: <unit>` and a `sources:` list. Each entry needs at least `id`, `name`, `publisher`, `family`, `urls`, `access`, `license` and `verification: {status: unverified, notes: ...}`; the format is in the `pipeline/core/registry.py` docstring.
- The loader checks each addition file on its own. A malformed file, an id already in `registry.yaml`, or an id that two addition files both add breaks only the units that own those files (and any unit using that id); everyone else keeps working. `test -k <unit>` includes `test_registry_additions_valid[<unit>]`.
- The file name must be an existing unit.
- The access policy (§4) applies to added sources too: set `access.requires` honestly.
- List the addition in your issues file; the orchestrator verifies it and merges it into the registry.

## 9. Logging problems: `docs/phase1/issues/<unit>.md`

Never edit `ISSUES.md`; the orchestrator merges your file into it. Use this format:

```
# <unit>: Phase 1 issues
| # | Severity | Issue | Impact / what the unit does | Status |
|---|---|---|---|---|
| <unit>-1 | major | Table 7 PDF has no text layer (scanned) | 2019-20 rows not ingested; gap_map R9 stays missing | OPEN |

## Framework requests
## Registry additions
## Revisions seen (pin changes)
```

- Log every blocked download, missing table, level break, closure failure, skipped item and assumption. SPEC rule 4 applies: no silent fallbacks.
- Severity: `blocker` (the gap-map cell cannot be filled), `major` (the data are incomplete or doubtful), `minor`.

## 10. Done means

1. `fetch <unit>` then `build <unit>` succeed, and `fetch <unit> --offline` succeeds.
2. `test -k <unit>` passes, including your value tests, and `test` has no failures that are yours. `repro <unit>` prints `REPRO OK`.
3. Every OFFICIAL gap-map ref your sources serve is declared in your coverage file, and `coverage <unit>` shows no `BROKEN`.
4. The module docstring states what is ingested, the vintage, and what is skipped and why. The issues file is up to date.
